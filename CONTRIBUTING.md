# Contributing to RepTracking

Thanks for helping improve RepTracking. Contributions of code, design,
documentation, testing, and product feedback are welcome.

## Before You Start

- Search existing issues before opening a new one.
- Use the bug report or feature request template when possible.
- For a substantial change, open an issue first so the approach can be
  discussed before implementation.
- Keep changes focused and avoid unrelated formatting or refactoring.

## Local Development

RepTracking currently has no dependencies or build step:

1. Fork and clone the repository.
2. Create a branch from `main`.
3. Open `index.html` in a modern browser.
4. Make and test your changes on both narrow mobile and desktop viewports.

## Pull Requests

- Explain the problem and the chosen solution.
- Link the related issue when one exists.
- Include screenshots or recordings for visible interface changes.
- Confirm that timer controls, set logging, and local persistence still work.
- Keep pull requests small enough to review comfortably.

## Commit Messages

Use short, imperative commit messages that describe the outcome:

```text
Add editable workout sets
Fix timer pause calculation
Improve narrow-screen controls
```

## Reporting Bugs

Include browser and operating system details, reproduction steps, expected
behavior, and screenshots when they help explain the issue.

All contributors must follow the [Code of Conduct](CODE_OF_CONDUCT.md).
